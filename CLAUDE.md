# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository overview

Personal finance dashboard. Single-page React app with no build step in the traditional sense — JSX is compiled in the browser by Babel Standalone, React is loaded via UMD CDN, and "bundling" is a Python script that concatenates files into one HTML.

There is **no `package.json`, no `node_modules`, no bundler, no test suite.** All tooling is Python.

## Commands

```bash
# Run dev server (multi-file mode, requires HTTP server because Babel can't fetch JSX over file://)
python -m http.server 8000        # then visit http://localhost:8000

# Generate data/data.js from your private CSVs (gitignored output)
python scripts/generate_data.py
DRIVE_DATA_DIR=/path/to/csvs python scripts/generate_data.py   # override default Drive path

# Bundle into single self-contained dist/index.html
python scripts/bundle.py            # live mode — empty data scaffold + drive-loader.js (auth at runtime)
python scripts/bundle.py --example  # synthetic demo mode — inlines data.example.js, skips Bootstrap auth flow

# Deploy
wrangler pages deploy dist --project-name=alon-ledger
```

There are no lint, type-check, or test commands — none are configured.

## Architecture

### Two data-loading modes (this is the key design split)

The app supports two completely different ways of getting data into `window.FinanceData`:

1. **Live mode** (default `bundle.py`, also dev mode via `index.html`): `data/data.js` is generated by `scripts/generate_data.py` from real CSVs. At runtime, `data/drive-loader.js` re-fetches CSVs from Google Drive over OAuth and **mutates the top-level arrays in place** (see `populateFinanceData` — `ACCOUNTS.length = 0; ACCOUNTS.push(...)`). The Bootstrap component in `app.jsx` orchestrates the sign-in / fetch lifecycle.

2. **Example mode** (`bundle.py --example`): `data/data.example.js` is inlined with synthetic data; `bundle.py` rewrites the entry point from `<Bootstrap/>` to `<App/>` directly, bypassing all auth.

When changing data shape, **all four touchpoints must stay in sync**: `data.example.js`, `generate_data.py` (Python writer), `drive-loader.js → buildFromCsvs` (JS transformer), and `helpers.js` (consumers).

### Script load order (matters!)

Both `index.html` (dev) and `bundle.py` (prod) load scripts in this exact order:

1. React + ReactDOM (UMD)
2. Babel Standalone
3. PapaParse + Google Identity Services (live mode only)
4. `data/data.js` — declares **mutable top-level consts** `ACCOUNTS`, `SNAPSHOTS`, `INCOME`, `EXPENSES`, `FX`, etc. and assigns `window.FinanceData`. These are arrays/objects so the loader can mutate their contents.
5. `data/helpers.js` — reads those globals, defines `window.Fin` namespace (formatters, derivations, color maps).
6. `data/drive-loader.js` — defines `window.DriveLoader` (live mode only).
7. JSX components in dependency order: `tweaks-panel.jsx` → `icons.jsx` → `charts.jsx` → tab components → `app.jsx`.

JSX components are loaded as `<script type="text/babel">` so Babel compiles them in-browser. There are **no ES modules and no imports** — everything communicates through globals (`React`, `window.FinanceData`, `window.Fin`, `window.DriveLoader`, and component names hoisted by Babel).

### Reactivity to data swaps

After live data populates, the loader calls `Fin.rebuildDerivations()` (defined in `helpers.js`) to refresh the `snapshotMap` cache. The Bootstrap component then re-renders App with `key={tick}` to force a clean mount. If you add new memoized derivations in `helpers.js`, add their cache reset to `rebuildDerivations()`.

### Currency model

All amounts are stored in **native currency** (ILS or USD). FX-to-ILS conversion happens at display time via `Fin.toILS(amount, currency, ym)`, which uses the historical rate `FX.byMonth[ym]` for that month, falling back to `FX.current`. The user can override `FX.current` interactively via the FX strip in the header — never write to `FX.byMonth` from the UI.

### Tab structure

`app.jsx` is the shell (header, FxStrip, tab nav, TweaksPanel). Each tab is a separate file in `components/`: `tab-overview.jsx`, `tab-accounts.jsx`, `tab-cashflow.jsx`, `tab-passive.jsx`. Charts (`LineChart`, donut, stacked bar, treemap) are hand-rolled SVG primitives in `components/charts.jsx` — **no Chart.js, no D3**. Match the existing chart patterns when adding new ones.

### Tweaks (settings) persistence

`tweaks-panel.jsx` defines `useTweaks` hook backed by localStorage. Defaults live in `app.jsx` between `/*EDITMODE-BEGIN*/` and `/*EDITMODE-END*/` markers — these markers exist so external tools can rewrite the defaults block; preserve them when editing.

## Demo data requirement

**Every feature or code change must be reflected in `data/data.example.js`.** When adding new fields, categories, accounts, or data structures, update the synthetic demo data so the change is visually exercised in example mode (`bundle.py --example`). Do not ship a feature that is invisible or broken in the demo build.

## Conventions

- **Globals over imports.** Add new shared utilities to `window.Fin` in `helpers.js`, not as ES exports.
- **Mutate, don't reassign.** The data globals are populated in place by `drive-loader.js`. Never `ACCOUNTS = [...]` — always `ACCOUNTS.length = 0; ACCOUNTS.push(...)`.
- **Privacy invariant.** `data/data.js` and `dist/` are gitignored. `data.example.js` is the only data file committed. Never commit real numbers.
- **Editorial-meets-terminal aesthetic.** Inter / JetBrains Mono / Newsreader fonts; ochre accent; oklch color space. Color maps for groups/categories/income types live in `helpers.js` (`GROUP_COLOR`, `CATEGORY_COLOR`, `INCOME_TYPE_COLOR`) — extend these when adding new categories rather than hardcoding colors in components.
- **Privacy mode** (`data-privacy="on"` on `<html>`) blurs numbers via CSS. Any element rendering a monetary value (via `Fin.fmtILS` / `Fin.fmtUSD` / `Fin.fmtSigned` / `Fin.fmtPct` for yields) must include `private` in its className. Hover reveals the value individually. For monetary values inline in mixed text, wrap just the number in `<span className="private">…</span>`.
- **Months as `YYYY-MM` strings** throughout. The canonical month list is `Fin.ALL_MONTHS` (currently 2024-05 through 2026-05; `monthsRange()` in `helpers.js`).

## Refresh / deploy workflow

After updating CSVs on Drive: just **refresh the deployed page** — `drive-loader.js` re-fetches at load time. Re-bundling/redeploying is only needed for **code** changes:

```bash
python scripts/bundle.py
wrangler pages deploy dist --project-name=alon-ledger
```

See `SETUP.md` for OAuth setup details (Client ID and Folder ID are baked into `data/drive-loader.js`) and `DEPLOY.md` for hosting alternatives.
